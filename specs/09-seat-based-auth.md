# 09: Seat/subscription auth (no API key required)

**What to build:** Support authenticating harness runs against providers that bill via seat/subscription (e.g. a Mistral Le Chat seat with OAuth device login) instead of a per-token API key. Today both adapters are API-key only: `mistral-api` sends `Authorization: Bearer $api_key_env` and refuses to run without it; `vibe-cli` inherits whatever the `vibe` binary finds in `MISTRAL_API_KEY` or the system keyring. Neither path can use an OAuth/seat token. Goal: a credential broker behind the existing `CredentialProvider` protocol (`adapter.py`) that can mint/refresh short-lived tokens from a seat session, inject them per-run under the same allowlist discipline (scrubbed env, no ambient secrets), and record only non-secret telemetry (which auth mode was used, token expiry) in the run manifest and audit log.

**Blocked by:** none (builds on 05 `providers.toml` + `CredentialProvider` seam; touches `adapter.py`, `providers.py`, settings, and the daemon's env handling)

**Status:** done (2026-11-12 — implemented as `src/turbochickens/seat.py` `SeatBroker` behind the `CredentialProvider` protocol; 166/166 tests green incl. `tests/test_seat_auth.py`)

- [x] A provider profile can declare `auth = "seat"` (OAuth device flow) in addition to `auth = "api-key"` (default, unchanged behavior) — `ProviderProfile.auth` + `oauth_device_url`/`oauth_token_url`/`oauth_client_id`/`oauth_scope`; a validator requires the OAuth fields for seat and rejects them for api-key; built-in defaults stay `api-key`
- [x] The credential broker stores the seat session under the data dir (never in job specs or the audit log) and refreshes expired tokens before a run — `SeatStore` keeps one 0600 JSON file per provider under `<data_dir>/seats/` (dir 0700); `SeatBroker._refresh` rotates the token via the token endpoint when expired (30s leeway); a revoked/expired refresh deletes the session and raises `SeatError` (fail closed)
- [x] Per-run env injection still allowlists only the resolved credential var; no ambient secrets leak (existing `build_per_run_env` guarantee holds) — the broker injects the seat access token under the provider's usual `api_key_env` name only; `vibe-cli`/api-key providers keep the env allowlist; verified by tests asserting `env_keys` carries names only
- [x] `mistral-api` adapter sends the seat-derived bearer token; runs without any credential still fail closed with a clear error — the adapter reads `run.env[api_key_env]` unchanged; missing seat session → `SeatError: no seat session … run 'tc auth login <provider>'` at prepare, zero HTTP requests sent (tested)
- [x] `vibe-cli` adapter path works with a seat-configured vibe profile — **finding:** vibe's own `config.toml` `ProviderConfig` `browser_auth_base_url` / `browser_auth_api_base_url` fields are honored by the `vibe` binary itself, and `HOME`/`XDG_CONFIG_HOME` are already in `BASE_ENV_KEYS`, so a browser-auth provider registered in `~/.vibe/config.toml` is picked up via HOME passthrough with no TurboChickens code; TurboChickens injects no credential in that case and the manifest records `auth.mode = "none"` (e2e-tested with a fake vibe binary asserting `home=set`, `mistral_api_key=unset`)
- [x] Run manifest records `auth_mode: api-key|seat` (+ token expiry), audit log records the mode per run; no tokens anywhere — manifest gains a top-level `auth: {mode, token_expires_at}` block; audit gains `auth.resolved` (mode + expiry) per run and `auth_mode` on `run.finished`; tests assert no token string appears in manifest or audit JSON
- [x] Cost/stats path (spec 08) still works: seat usage reports zero per-token cost or seat-pool telemetry, never a fabricated per-token price — seat runs record `usage.cost_usd = 0.0` + `usage.billed_via = "seat"`, and `expected_cost_usd` in `job_usage_stats` is 0.0 for seat providers
- [x] Tests: fake seat broker (mock OAuth server on loopback) → run succeeds with no `*_API_KEY` in env; expired token → refresh → success; revoked seat → fail closed; existing API-key tests unchanged — `tests/test_seat_auth.py` (21 tests: provider/store pure seams, broker + adapter contract over MockTransport, device flow over loopback, CLI `tc auth login/status/logout`, and 4 daemon e2e cases); all 145 pre-existing tests still pass unmodified

**How to use it:** declare `auth = "seat"` + OAuth endpoints on a provider in `providers.toml` (see `examples/providers.toml` for a commented Le Chat example), run `tc auth login <provider>` once (device flow: it prints the verification URI + user code and polls), then `tc run` jobs with `model = "<provider>/<model>"` — no `*_API_KEY` needed. `tc auth status` shows each provider's mode + session expiry (never tokens); `tc auth logout <provider>` deletes the session.
